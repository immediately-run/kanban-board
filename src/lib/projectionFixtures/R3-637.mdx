### Requires

- `npm-publish` — the `ui-releases` workflow pins an exact `@immediately-run/cli@<x.y.z>`, and that version must exist on npm before the workflow can run. An agent without publish rights lands all three PRs with tests green and leaves the last two exit criteria unticked, handing the publish + first workflow run to [[R3-639.mdx]]'s operator.

## Why

The registry pins commits the app repos' own Pages evict: R3-624 publishes `<sha>.zip` beside the branch zip, but each Pages deploy REPLACES the site (ZIP_CACHE_AUTOMATION §5.3), so a stable pin older than head 404s to the REST loader on every cold boot. The standing `base` lock covers 8 of ~25 `BUILD_DEFAULTS` regions (stale since 2026-06). And "testing" needs a moving pointer that immutable-by-name ([[../specs/UI_RELEASES_SPEC.mdx#sec-3-3]]) forbids being a release.

## What to build

1. site-main: `scripts/export-release-base.ts` + `npm run export:release-base` — emits the authoring base map (every `BUILD_DEFAULTS` region → its build-default repo at `@main`) as JSON for commit into the registry repo.
2. cli: `pin-release` bakes `zips/<ns>/<repo>/<sha>.zip` for every lock entry — materialize the commit, build via the cache-zip core, refuse differing bytes at an existing path.
3. cli: `--channel <name>=<release>` repoints `index.json.channels`; a name that is both a release and a channel is an error.
4. cli: `--check` gains the coverage assertion — the base lock must cover every region the committed derived map names.
5. ui-releases: `testing.json` authoring (extends base, `@main`) + the scheduled `testing` workflow.

## Architecture — the decisions, named

- **The export runs with `tsx`, not strip-types.** `node --experimental-strip-types` cannot import `defaults.ts` — its VALUE import `'./capabilities'` is extensionless and fails `ERR_MODULE_NOT_FOUND` (verified 2026-09-15); the `.mts` generators work only because their import graphs are value-clean. Add `tsx` as a devDep and run `tsx scripts/export-release-base.ts`; the script imports `BUILD_DEFAULTS` directly and writes `{"<region>": "provider:ns/repo@main"}` per region. Reason: the CLI keeps no cross-package dependency (its own header rule, `src/release.ts:3-5`), and a hand-kept region copy is exactly the drift this exists to remove.
- **The bake reuses the cache-zip CORE, extracted.** Extract `buildCacheZip({ repoPath, ref, out })` from `src/commands/cacheZip.ts` (the `git archive` + sidecar + artifacts core around `:474-482`) so `src/commands/pinRelease.ts` is the second caller. The engine archives `HEAD` only — so `pin-release` materializes each pin first: `git clone --filter=blob:none --no-checkout` + fetch the sha + `git checkout <sha>` into `os.tmpdir()`, and the builder runs with HEAD === the pin and `ref: <sha>` (the sidecar coordinate a §6.4 host matches). Never bake a working tree.
- **Channels are one optional index field.** `ReleaseIndex.channels?: Record<string, string>` in `src/release.ts` (`:96`); `buildIndex` carries it through; `--channel` is the ONLY mutable write the flow performs (§5 7a). A channel whose target is not a published release → error naming both.
- **Coverage is a loud publish-time gate.** `--check` reads the committed `defaults-map.json` (the export's output, committed to the registry repo) with `JSON.parse` and fails listing every region the base lock omits — the §3.1 anti-drift rule. A script never parses TypeScript source.
- **The testing workflow writes the Pages-serving branch, never `main`.** `main` is the reviewed authoring surface (R-TA-1's ruleset); the workflow (scheduled + `workflow_dispatch`) runs steps 3–5 + 5a + 7a over `testing.json` and pushes locks/zips/index to the branch GitHub Pages serves. Read the repo's existing `publish.yml` + README first and match its Pages source; if the source/settings need a flip, that leg belongs to [[R3-639.mdx]] (`github-admin`) — land the workflow file and say so in the PR.
- **Failure is loud and aborting.** A pin that cannot be materialized aborts the publish naming repo+sha; differing bytes at an existing `zips/` path abort naming the path (immutable, §3.4); a missing derived map in `--check` fails naming the file.
- **Do not:** mutate an existing lock name or zip path; bake from a working tree; invent a second index field for zip locations (paths are derived, §8); let the workflow commit `main`; parse `defaults.ts` with a regex or a hand-copied region list.

## Tests

- cli `test/release.test.mjs` (extend; `node --test`, never jest): `channels` round-trips through `buildIndex`; `--channel` repoint updates only that field; a dual name (release AND channel) errors.
- cli `test/cacheZipBase.test.mjs` (extend the local-git-fixture pattern): bake at a pinned sha — the zip's sidecar carries `ref === <sha>` and `commitSha === <sha>`; a second bake with changed bytes at the same path aborts.
- cli coverage: a fixture `defaults-map.json` naming a region the fixture base lock omits → `--check` fails listing it (fixture shaped from the real generator output).
- site-main: a small jest case runs the export over the REAL `BUILD_DEFAULTS` and asserts the emitted region count equals `BUILD_DEFAULTS.length`.
