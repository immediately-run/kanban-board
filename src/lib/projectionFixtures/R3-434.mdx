## The gap

The sandbox's `show-error` action forwards `error.path` / `error.line` / `error.column` when the
`BundlerError` carries them (`src/errors/util.ts`), and the host's `mapShowError` copies them
verbatim. For a **transform** error (Babel), none are populated: the message reads
`App.tsx: Cannot access 'off' before initialization (41:6)` and every field is absent. The Tools
panel therefore lists a build error that names its own position as "not file-located", and a click
cannot navigate to it — while a runtime error (with stack frames) IS located.

## What to build

- Populate `path` (repo-relative) and `line`/`column` on the `BundlerError` for transform
  failures from the Babel error's `loc` (and its filename), so the wire carries them like a
  runtime error's do. No change to the host: `mapShowError` already forwards them.
- Do NOT parse positions out of message text on the host side — the message is untrusted
  display data and a bare basename (`App.tsx`) is not a repo path.
